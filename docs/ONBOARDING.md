## Часть 1. Суть продукта

### Бизнес

**Аквафор Pro.Store (бренд PROSTOR)** — компания монтирует и обслуживает системы водоочистки: фильтры под мойку, предфильтры на стояк, умягчители для коттеджей, промышленные осмосы. Это **не доставка воды** — это продажа оборудования + монтаж + сервис (замена картриджей, ремонт, диагностика, анализ воды).

Демо-лендинг: https://aquaphor-pro.store/

**Модель — агрегатор:**

- Товары продаёт партнёр (ИП Ефимов и др.) → компания получает комиссию
- Услуги выполняет мастер (самозанятый/ИП) → компания получает комиссию
- Приложение связывает клиента, товар и мастера
- В МойСклад это отражено через CommissionReportOut (отчёт комиссионера) на каждый заказ

**Экономика:** товары — 93% продаж, но маржа 29% и стагнация. Услуги — только 7% продаж, но маржа 58% и потенциал роста (сейчас на услугах работает 2 мастера вместо прежних 12) — стратегически услуги важнее, чем доля продаж показывает.

**Средний чек:** товар 5-40К ₽, монтаж 1.5-11К ₽, замена картриджей 1-3К ₽.

### Кто пользуется приложением

| Роль                          | Что делает                                                                                                                                                                                                          |
| ----------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **CLIENT**                    | Выбирает товар в каталоге → опционально добавляет услугу монтажа → выбирает дату/мастера → оплачивает → мастер приезжает. После установки — напоминания о замене картриджей (recurring revenue)                     |
| **SERVICE** (мастер)          | Получает заказы с маршрутом на день, выезжает, выполняет работу, заполняет гарантийный талон, получает оплату (самозанятый/ИП)                                                                                      |
| **CURATOR** (куратор)         | Видит все заказы, назначает мастеров, управляет зонами обслуживания, контролирует качество, меняет роли пользователей (в т.ч. выдаёт роль MANAGER)                                                                  |
| **MANAGER** (B2B, новая роль) | Представляет коммерческие объекты (кафе, фитнес-клубы, медцентры и т.д.), создаёт для них заказы на обслуживание. Роль выдаётся только куратором/админом — самостоятельная регистрация как MANAGER не предусмотрена |
| **ADMIN**                     | Полный доступ                                                                                                                                                                                                       |

**Один пользователь = один аккаунт**

Приложение было Telegram Mini App-only. Риски: блокировка Telegram, зависимость от Telegram Payments, ограниченная аудитория. **Курс сменился на web** — вся разработка — в web.

### Ключевые фичи продукта

- **Каталог товаров** — фильтры, картриджи, комплектующие (ISR/SSG для SEO)
- **Корзина** — Zustand + sync с бэкендом после логина, работает и гостю
- **Оформление заказа** — дата, мастер, оплата (ЮKassa)
- **Личный кабинет клиента** — заказы, профиль, гарантии, объекты недвижимости
- **Карта качества воды (`/water`)** — MapLibre GL карта с heatmap/predict по качеству воды, зоны обслуживания. Экспериментальный "water-pivot" — карта-first UX
- **Smart Search** — мультимодальный AI-поиск (текст + фото) поверх карты воды: distiling backend slovo делает vision-анализ фото и подбирает оборудование (`vision + matchScore`)
- **Чат по заказу** — общение клиент↔мастер по конкретному заказу
- **Dashboard мастера** — заказы на день, маршрут (OSRM), расписание, зона обслуживания, квалификация, транспорт
- **Dashboard куратора** — все заказы, зоны, назначение мастеров, управление ролями
- **B2B (MANAGER)** — управление коммерческими объектами, публичная карта объектов
- **PWA** — устанавливаемое приложение, push-уведомления
- **Аутентификация** — email/пароль + Telegram Login (в процессе), единая сессия через собственный JWT-флоу

### Бизнес-цель приложения

1. Каталог → находит нужный фильтр
2. Услуги к товару предлагаются в момент покупки
3. Оформление в 2-3 тапа
4. Повторные заказы (напоминания о замене картриджей)
5. Маршрутизация мастеров (OSRM)
6. Зоны обслуживания

## Часть 2. Статус разработки

### Стек (кратко)

Next.js 16 + React 19 + TypeScript + Tailwind 4 + DaisyUI 5, TanStack Query + Zustand + React Hook Form + Zod, MapLibre GL (карта), Vitest + Playwright (тесты). Архитектура — **Feature-Sliced Design 2.1** (`app → views → widgets → features → entities → shared`)

**Backend** — отдельный репозиторий `crm-aqua-kinetics-back` (NestJS), уже задеплоен, фронт только потребляет API.

### Что уже реализовано в коде (проверено по `src/`)

- **Каталог, подкаталог, карточка товара** (`views/catalog`, `views/sub-catalog`, `views/product`)
- **Корзина + checkout** (`views/cart`, `views/checkout`, `features/cart`, `features/checkout`)
- **Заказы** (`views/orders`, `views/order-detail`, `views/order-chat`, `views/order-feedback`)
- **Профиль, адреса, объекты недвижимости** (`views/profile`, `views/addresses`, `features/real-estate`, `features/address-search`)
- **Карта воды + Smart Search** (`views/water-map`, `features/smart-search`, `features/product-search`)
- **Dashboard мастера** (`views/dashboard` + `features/master-*`: schedule, location, service-area, qualification, vehicle, work-days, access-gate)
- **Dashboard куратора** (`features/curator-access-gate`, `(dashboard)/curator`)
- **Push-уведомления** (`features/push-notifications`)
- **Auth** (`views/auth`, `features/auth`) — регистрация, вход, подтверждение почты, восстановление пароля

### Бэклог / отложенное (не блокирует текущую работу)

- **401 console noise при cold load** (`docs/backlog/401-auth-refresh-console-noise.md`) — не баг, просто шумные логи в консоли на старте `/water` и других auth-gated страниц; отложено, не приоритет
- **Chat polling strategy** (`docs/backlog/chat-polling-strategy.md`) — `useInfiniteQuery` + `refetchInterval` рефетчит все загруженные страницы чата, а не только последнюю; приемлемо пока чаты короткие, станет проблемой на длинных чатах (100+ сообщений)
- **Address-flow chip → RealEstatePicker** — chip «📍 По адресу» в smart-search сейчас только префиллит запрос, полноценный reuse компонента выбора объекта — Phase 1.5
