<objective>
Build the one genuinely new page this phase introduces: /telegram-register, the Telegram registration-completion form (TG-02) plus the two failure states that exist nowhere else in the app — the mid-flow "session expired, restart" state (TG-03) and the email-conflict redirect (TG-04). Close the routing gap by guarding the new route in proxy.ts.

Purpose: A brand-new Telegram profile detected in Plan 01 lands here to finish creating a real account (email + phone + consents, no password). The TG-03/TG-04 states make the flow fail safely instead of silently — an expired one-time token restarts cleanly, and an already-registered email is disclosed and redirected to email login rather than creating a duplicate account.
Output: telegram-register-page.tsx (form + 2 replacement states), its thin route wrapper, a views/auth barrel export, and the proxy AUTH_ONLY guard.
</objective>

## Phase Goal (MVP user story)

**As a** user, **I want to** authenticate or register entirely through Telegram from the auth screen built in Phase 2, **so that** new accounts are detected correctly and email conflicts are handled gracefully instead of creating duplicate accounts.

This plan delivers the new-account completion half of that story (TG-02) and the graceful-failure halves (TG-03 restart, TG-04 conflict).

## Trust Boundaries

| Boundary                                    | Description                                                                                 |
| ------------------------------------------- | ------------------------------------------------------------------------------------------- |
| sessionStorage → page                       | registrationToken/profile read on mount; page must fail closed if absent                    |
| Telegram-supplied profile → DOM             | first_name/last_name/photo_url rendered in the completion form                              |
| browser → backend (/auth/telegram/register) | untrusted form + registrationToken; backend is authoritative on TTL/one-time/email-conflict |

| --------- | --------------------------- | -------------------------------- | -------- | ----------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| T-03-04   | Elevation / Access Control  | /telegram-register route         | high     | mitigate    | Added to proxy.ts AUTH_ONLY (authenticated users redirected away); page also fails closed — no valid sessionStorage token → TG-03 restart state, the form never renders on client-visible state alone.                                                               |
