<objective>
Ship the tail end of the TG-04 flow: after a Telegram user hits an email conflict and logs in by email, offer them a «Привязать Telegram» affordance on their profile — as a disabled, honest placeholder (the actual linking is Phase 4 / LINK-01). The row appears exactly once, only for users who arrived via the conflict-then-email-login path, using the same one-shot sessionStorage-flag mechanism as Phase 2's registration notice.

Purpose: Delivers the "offered «Привязать Telegram» after logging in there" clause of TG-04 without over-promising a feature that isn't built yet — mirroring the disabled-affordance precedent the login page's own Telegram button set before this phase wired it up.
Output: A one-shot TelegramLinkHintListener (or hook), a public export, and the conditionally-rendered disabled row on profile-page.tsx.
</objective>

## Phase Goal (MVP user story)

**As a** user, **I want to** authenticate or register entirely through Telegram from the auth screen built in Phase 2, **so that** new accounts are detected correctly and email conflicts are handled gracefully instead of creating duplicate accounts.

This plan delivers the graceful-recovery affordance at the end of the TG-04 email-conflict path.
